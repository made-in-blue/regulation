# MADE in BLUE HACKATHON ルールブック

## 1\. 本ルールについて

本ルールは、MADE in BLUE HACKATHON（以下「本大会」）における提出・審査に関する規程（以下「本ルール」）です。

* 開催期間: 11/13(金)〜11/28(土)。キックオフは11/13(金) 20:00です。最終発表（Demo Day）は11/28(土)に行います。

## 2\. 審査対象

本大会では、次の4つを審査対象とします。

### 2.1 発表内容

Demo Day（11/28）での発表です。事業アイデアの内容とデモを見ます。

### 2.2 リーンキャンバス

チームが作成するリーンキャンバスです。提出先と期限は第6章に書きます。

### 2.3 GitHub

各チームに割り当てられたGitHubリポジトリにpushされたソースコードのうち、mainブランチにあるもので、本大会の開催期間からコードフリーズまでに参加者が記述したもの（AI生成を含む）を、審査対象とします。  
次のものは、審査対象としません。

* mainブランチ以外にあるソースコード  
* 外部ライブラリのファイルであると認められたもの  
* 本大会の開催期間より前に記述されたと思われるもの  
* フレームワーク等のテンプレート  
* 上記に類するもの

組織力の評価では、コード（mainブランチ）のほか、GitHub Projects、issueなど、コード以外の活動も活動の記録として確認することがあります。

### 2.4 コミュニケーション成果物

チームのDiscord上のやりとりと、活動ログです。活動ログとは、チームが活動の記録として残したもの（議事録、タスクの記録、担当表など）です。形式やツールは問いません。ただし、確認に多くの手間や時間がかかる（認知負荷が高い）と運営が判断したものは、評価の対象にならないことがあります（第7章）。

### 2.5 生成AIの利用

生成AIの利用は可能です。コードや文書づくりに使えます。発表スライドを生成AIで作ることは、推奨しません。

## 3\. 審査項目と審査対象の対応

◎は主に見るもの、〇は補助として見るもの、－は見ないものです。

|  | 発表内容 | リーンキャンバス | GitHub | コミュニケーション成果物 |
| :---- | :---- | :---- | :---- | :---- |
| 組織力 | 〇 | － | 〇 | ◎ |
| 事業性 | ◎ | ◎ | － | － |
| 発表 | ◎ | － | － | － |
| 成果物 | ◎ | － | ◎ | － |

## 4\. 組織力の評価

組織力は、チームワークや活動の活発さを見る項目です。発表だけでなく、チーム内のコミュニケーションも評価に入れます。

### 4.1 見る観点

次の5つの観点を、それぞれ1〜5点で付けます。

| 観点 | 1点 | 5点 |
| :---- | :---- | :---- |
| 意思疎通 | メンション付きの連絡に反応がない日が続く。決定事項がどこにも残っていない | メンション付きの連絡に、翌日までを目安に返信している。決定事項が活動ログなどに残り、あとから確認できる |
| 役割分担 | 役割が決まっていない、または決めても使われていない | 役割と担当が見える形（WBS、GitHub Projectsなど）で決まり、必要に応じて見直されている |
| 貢献のバランス | 1人が成果物の大半を担っている | 担当が分散し、各自の得意や関心が成果物に表れている。コード以外も含む |
| 相互支援 | 困っている人への助けがなく、意見が分かれると議論が止まったまま | 困っている人を他のメンバーが助けている。意見が分かれても、理由を出し合い、結論と理由が記録されている |
| 継続的な取り組み | 更新が長期間止まっている | 期間を通して更新が途切れず、成果物が少しずつ育っている |

### 4.2 確認場所

チームのDiscord、活動ログ、GitHubです。DMや通話など確認が困難であると運営が判断したものは、対象外とします。

### 4.3 連絡への反応

メンション付きでDiscordに投稿した連絡には、翌日までを目安に返信するなど、連絡はまめに取りましょう。  
時刻は、Discordの記録で確認します。DMとボイスチャットでの連絡は確認できないため、対象外です。大事な連絡や決めたことは、DMではなくチームのチャンネルに残してください。

### 4.4 評価に使う記録と、評価の単位

* 使う記録  
  * Discord: 自チームのカテゴリ内のチャンネルの内容  
  * 活動ログ: 議事録、タスクの記録、担当表  
  * GitHub: 自チームのリポジトリ。コード（mainブランチ）のほか、GitHub Projects、issueなど、コード以外の活動も記録として見ることがあります。  
* 対象期間: 開催期間の開始から11/28(土) 00:00までです。  
* 評価の単位: チーム単位です。5観点を1〜5点で付け、1つの組織力の点にします。  
* 反応の見方: メンション付きの連絡1件ごとに、最初の反応までの時間を見ます。点は全体の傾向で付けます。  
  * 例: 10件中1件が2日遅れても、それだけで1点にはしません。  
  * 時刻はDiscordの記録で確認します。

## 5\. 審査の方法

最終発表は11/28(土) 10:00〜11:30、Gスクエア（MADE in BLUE FES内）で行います。

### 5.1 採点する人

* 事業性・発表・成果物: 審査員が最終発表で採点します。審査員は3人とします。  
* 組織力: 運営が記録で事前に採点し、最終発表の様子を見て確定します。

### 5.2 配点

| 項目 | 配点 |
| :---- | :---- |
| 組織力 | 35点 |
| 事業性 | 25点 |
| 成果物 | 20点 |
| 発表 | 20点 |
| 合計 | 100点 |

### 5.3 同点の扱い

総合点が同じときは、組織力の点が高いほうを上位とします。それでも同じなら事業性の点が高いほう、それでも同じなら審査員の協議で決めます。

### 5.4 賞の選び方・結果通知

* 賞の選び方: 総合点で決めます。  
* 結果通知: 総合点と項目別の点を、チームに返します。

### 5.5 持ち時間

* 1チームの持ち時間は8分です。内訳は、発表5分、質疑応答2分、入れ替え1分です。  
* デモは、発表の時間に含まれます。ライブのデモが動かない場合に備えて、デモ動画を用意することをおすすめします。  
* 時間になったら、途中でも打ち切ります。時間を超えたこと自体に対する減点はありません。

### 5.6 質疑応答

* 質問は審査員が行います。  
* 答えるメンバーは問いません。

### 5.7 表現の制限

次のものは使えません。運営が発表を止めることがあります。

* 個人や団体への誹謗中傷、差別的な表現  
* 他の人の著作物、ロゴ、写真、個人情報を、許可なく使うこと  
* 会場に迷惑がかかる大きな音、強く点滅する光

### 5.8 録画・配信

* 運営は最終発表を録画します。録画は審査の確認と運営の記録に使い、公開しません。  
* 配信も行いません。  
* 録画を公開する場合は、事前にチームの同意を得ます。

## 7\. 審査上の注意

### 7.1 受け付けないもの

確認に多くの手間や時間がかかるもの（認知負荷の高いもの）は、受け付けません。たとえば、次のものです。

* 提出時に共有リンクが開けないもの（閲覧権限がない、期限が切れているなど）  
* 通話の録音など、内容を確認するのに長い時間がかかるものを、そのまま提出したもの

提出前に、自分以外のアカウントでリンクが開けることを確認してください。

### 7.2 数と編集について

* 投稿やコミットの数が多いだけでは、高い点になりません。内容のない連投や、変更のないコミットは評価しません。  
* 第6章の期限より後に書き足した記録、書き換えた記録は、評価しません。活動ログは、編集の履歴が残るツール（Googleドキュメント、Notionなど）で作ってください。

### 7.3 記録の閲覧について

* チームのDiscord、活動ログ、GitHubは、審査のために運営と審査員が見ることがあります。自チームのカテゴリは、担当メンターも見られます。他のチームには見えません。  
* 見た内容は、審査と結果の連絡以外には使いません。
